OpenTelemetry debugging without leaving VS Code

An OTLP receiver built into your editor. Inspect traces, logs, metrics and a service map next to your code, jump from a span or log to its source line, and — if you want — ask Copilot why a request was slow. No Collector, Jaeger or Grafana to run.

Why this extension

Skip the local observability stack

Looking at telemetry during development usually means running a Collector and a backend, then switching between the browser and your editor. This moves that first round of investigation into VS Code.

Features

Everything you need for the debug loop

Logs, traces and metrics from every instance of every service, correlated with each other and with your source code.

Traces & waterfall

  • Query bar: service=checkout status=error dur>200ms
  • Waterfall merges spans from every instance
  • Each span's logs shown right on its bar
  • Find a trace by ID or pasted traceparent

Logs

  • Virtualized table with text, level, attribute and time filters
  • Promote any attribute to its own sortable column
  • Jump from a log to its trace or source line
  • Export OTLP/JSON, JSON or CSV; import JSON Lines

Metrics

  • Gauges, counters, histograms and summaries
  • Table or graph view per instance
  • Rate, stacked area, percentiles and more
  • Over-time aggregation and series roll-up

Service map

Services, databases, queues and external dependencies inferred from spans, so you can see what a request actually touches.

Jump to code

Spans and logs with code.* attributes open the exact source line in your workspace — no copy-pasting file paths from a browser.

Built-in OTLP receiver

OTLP/gRPC on 4317 and OTLP/HTTP (protobuf + JSON) on 4318, bound to 127.0.0.1. The endpoint is injected into apps you run or debug from VS Code.

Ask Copilot opt-in

The @otel chat participant and nine read-only tools explain slow and failing requests, citing the trace and span IDs.

Save & share sessions

Save traces, logs and metrics to one .otel.json file. A teammate loads it and gets the same waterfall, logs, charts and service map.

Private by design

No backend and no outbound calls. Telemetry lives in memory, bounded by retention settings, and is never written to disk unless you export it.

Quick start

Up and running in a minute

Works whether your app is launched from VS Code or runs somewhere else on your machine.

Install

Search “OpenTelemetry” in the Extensions view, or run:

code --install-extension SukantaSaha.opentelemetry

Start the receiver

Open the OpenTelemetry view in the Activity Bar and click Start receiver. The status bar shows the active gRPC and HTTP ports.

Send telemetry

Run or debug your app from VS Code — OTEL_EXPORTER_OTLP_ENDPOINT is injected for you. For apps started elsewhere, point the exporter at the receiver:

# Any OpenTelemetry SDK
export OTEL_EXPORTER_OTLP_ENDPOINT="http://127.0.0.1:4317"
export OTEL_EXPORTER_OTLP_PROTOCOL="grpc"
export OTEL_SERVICE_NAME="my-service"
import { NodeSDK } from '@opentelemetry/sdk-node';
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-grpc';
const sdk = new NodeSDK({
  traceExporter: new OTLPTraceExporter({ url: 'http://127.0.0.1:4317' }),
});
sdk.start();
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
exporter = OTLPSpanExporter(endpoint="http://127.0.0.1:4317", insecure=True)
exporter, _ := otlptracegrpc.New(ctx,
  otlptracegrpc.WithEndpointURL("http://127.0.0.1:4317"),
  otlptracegrpc.WithInsecure())
builder.Services.AddOpenTelemetry()
  .WithTracing(t => t.AddOtlpExporter(o => o.Endpoint = new Uri("http://127.0.0.1:4317")));
# OpenTelemetry Java agent / autoconfigure
-Dotel.exporter.otlp.endpoint=http://127.0.0.1:4317 -Dotel.exporter.otlp.protocol=grpc

Tip: OpenTelemetry: Show Instrumentation Snippet gives you these with your actual ports filled in.

AI investigation · optional

Ask Copilot why it's slow

Answers are computed from the telemetry the receiver holds, and every one comes with buttons that open the trace, span, logs or source line it refers to.

/slowFinds the slowest recent request and explains where the time went.
/errorsGroups failing requests by endpoint and explains the top failure.
/agentSummarizes the latest AI-agent run: LLM vs. tool time, tokens, failed tools.
  • Off by default. Enable the otel.ai.enabled user setting; a workspace can't turn it on.
  • Read-only & confirmed. Nine otel_* tools; VS Code asks before each call.
  • Redacted first. Secrets, tokens and AI prompt text are masked before anything reaches the model.

Privacy

Your telemetry never leaves your machine

The extension has no backend and makes no outbound network calls of its own. Its only network activity is the OTLP receiver listening for your apps.

your app ── OTLP ──▶ 127.0.0.1:4317 (gRPC) / 127.0.0.1:4318 (HTTP) ──▶ in-memory store in VS Code

Localhost only

The receiver binds to 127.0.0.1 by default. Exposing it to a network is an explicit choice via otel.host.

In memory, bounded

Capped by otel.retention.* and dropped on restart or Clear Collected Data. Nothing is written to disk unless you export it.

Untrusted by default

The AI model is told never to follow instructions in telemetry, and buttons are built only from IDs the extension validated.

FAQ

Questions, answered

Do I need to run an OpenTelemetry Collector?

No. The extension is the receiver. If you already run a Collector, add the extension as an extra OTLP exporter target and send data to both.

Which languages and SDKs are supported?

Anything that speaks OTLP over gRPC or HTTP (protobuf or JSON): Java, .NET, Go, Node.js, Python, Rust and more.

My app doesn't run from VS Code. Can I still use it?

Yes. Use Copy OTLP Endpoint or Show Instrumentation Snippet and point your exporter at http://127.0.0.1:4317 (gRPC) or http://127.0.0.1:4318 (HTTP).

Where is my data stored?

In memory only, bounded by the otel.retention.* settings. To keep a copy, use Save Session… and load it later with Load Session….

Does the AI feature send my telemetry anywhere?

Only when you enable otel.ai.enabled and ask a question. Results are redacted, size-capped and sent only to the chat model you selected in VS Code — including local or bring-your-own-key models. Details.

Can I open telemetry captured in CI or by a Collector?

Yes. Load Session… accepts saved sessions, bare OTLP/JSON requests and the JSON Lines written by the Collector file exporter.

Is it free?

Yes — free and open source under the Apache License 2.0. If it helps you, consider sponsoring or starring the repo.
